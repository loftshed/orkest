# Orkest Architecture & Module Map

Orkest is a cross-harness multi-agent orchestrator and spare-token software factory across Claude Code, Codex, Antigravity (Gemini), and OpenCode.

It is one product with one version, not a Claude Code plugin. `install.sh` links `ork` and `monitor` onto `PATH`, links the skills into each harness's skills directory, writes the commands, and registers monitor's MCP server; every harness calls `ork`. `ork update` fast-forwards the checkout and reruns that wiring. A leftover plugin install from before the change is reported, with the commands to remove it, and never removed automatically.

Orkest ships one runtime. The CLI entry points live in `src/bin/`, the Node modules in `src/lib/`,
and the Python coordinator and mailbox in `src/py/`. Both languages read the registries in
`references/`. Harness-facing commands, skills, OpenCode statusline, Plasma widget and macOS front ends live in
`adapters/`. Herdr and Orca discover their manifests at the checkout root.

## 3. Core Runtime Contracts

### A. Lease-Backed Workboard (`leaseExpiresAt` & `handoff` Packets)

- **TTL Leases & Heartbeat Renewal**: Claiming a workboard item sets a `leaseExpiresAt` timestamp (default 15-minute TTL), renewed on `ork progress` heartbeats (`agent_progress.py`) and `checkpoint` mutations. Expired or owner-absent items remain in `claimed`/`blocked` with `leaseExpired: true` and `recoveryNeeded: "lease_expired"` (or `"owner_absent"`), can be atomically taken over via `claim` / `reclaim` (or returned to `open` via `recover`), and bump `revision` on takeover so stale writes fail compare-and-swap with `"work revision conflict: current revision ..."` (`stale_revision`).
- **Structured `handoff` Packets**: `checkpoint`, `release`, and `submit` accept a structured `handoff` object (`files_touched`, `decisions_made`, `remaining_steps`, `blockers`, `verification_command_run`) so a successor agent or reviewer can resume without re-discovering context.

### B. Scoped Verification Gates (`--verify`, `--acceptance`, `foundry-state.json`)

- **Foundry Evaluation Contracts**: `ork foundry` (configured and tracked via `foundry-state.json`) and task specs support scoped `--verify` (`verify_cmd`) and `--acceptance` (`acceptance_criteria`) flags.
- **Post-Builder Verification**: Builders run scoped verification commands (capped at `--maxWorkers=2`) outside the model after handoff, paired with acceptance criteria checks before a worktree advances to `ork smelter`.

### C. Herdr Integration (`herdr pane report-metadata`, plugin actions)

- **Pane Metadata & Notifications**: In Herdr, `agent_terminal.py` reports display-only title and agent text after checking the native session. The display agent carries the count of observed busy children (matched by explicit parent session, account and checkout) with their model/effort provenance; the sync key includes that summary, so it clears when the count drops. Metadata is re-verified and re-reported at least every 90 seconds or when the pane's terminal ID changes, because a restarted server keeps no labels. Children never change the parent's `idle`/`done` status. Herdr owns lifecycle state; the Horde View subscribes to Herdr lifecycle events over the server socket to invalidate cached state and sends attention notifications for blocked workers and completed swarms. In the embedded view pane, a bare `q` closes only when pressed twice.
- **Interactive Pane Focus, Inventory & Actions**: Pressing `o` in Horde View focuses a verified agent pane (and `orca-worker.mjs` pairs with [`orca-plugin.json`](../orca-plugin.json) for Orca IDE workspaces and views), and `herdr_swarm_restore.py --inventory` provides a read-only reconciliation of Orkest bindings against passive Herdr snapshot and process inventory across five dimensions (`pane_existence`, `available_shell`, `live_agent_conversation`, `executing_worker`, and `accepted_task`). The [plugin manifest](../herdr-plugin.toml) declares the room pane, open/close/toggle actions, a startup hook for cold layout restores, and a `pane.closed` hook that keeps a view closed with Herdr's own close-pane closed. Herdr registers the shortcut through `[[keys.command]]`.

## 4. IDE & IntelliSense Setup

- **JavaScript / `.mjs`**: Configured via root [`jsconfig.json`](../jsconfig.json) (`NodeNext` module resolution). Exported functions across `src/lib/*.mjs` include JSDoc `@param` and `@returns` annotations for VS Code / Cursor / Antigravity hover tooltips.
- **Python / `.py`**: Configured via root [`pyrightconfig.json`](../pyrightconfig.json) (`extraPaths` pointing to `src/py` and `tests/src/py`) so Pylance/Pyright resolves sibling script imports and renders PEP 257 docstrings and type annotations on hover.
